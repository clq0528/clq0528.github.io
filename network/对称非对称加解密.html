安全加密技术架构指南

基于 RSA、AES、SHA 算法与 X.509 证书体系，构建端到端加密通信模型。

1 对称加密：AES 逻辑 AES-256-GCM

特点：加解密使用同一密钥。速度极快，适合大数据量加密，但密钥分发是痛点。

特点：公钥加密/私钥解密。解决密钥交换问题，速度较慢，适合加密小量数据（如密钥）。

1 发送端 (Sender)：打包加密与签名 Encrypt & Sign

组合拳：用 SHA 摘要，用 RSA 私钥签名，用 AES 加密正文，用 RSA 公钥加密 AES 密钥。

形象化理解：三位一体的包裹
🔐
密文 (Ciphertext) AES
这是一个巨大的保险箱，里面装着你的大文件。它是用 AES 钥匙锁上的。
🏷️
签名 (Signature) SHA + RSA
这是贴在保险箱上的防伪封条，由发送者私钥盖章，确保没被掉包。
✉️
加密后的密钥 RSA 加密
这是一个小信封，里面装着那把 AES 钥匙。它是用接收者的 RSA 公钥封死的。
技术选型：追求速度与安全的平衡
⚡ 性能差距
AES 极快，适合 GB 级文件。RSA 处理大文件会导致 CPU 飙升。
📏 长度限制
RSA 只能加密比密钥还短的数据（例如 256 字节以内）。
✔ 结论：用 AES 加密内容（求效率），用 RSA 加密 AES 钥匙（求安全分发）。
📤 发送端 (Sender)
生成随机 AES 密钥 (一次性)
用 AES 密钥加密大文件 → 密文
取出接收者的 RSA 公钥
用 RSA 公钥加密 AES 密钥 → 加密后的密钥
打包：[密文 + 加密密钥 + 签名]
📥 接收端 (Receiver)
取出自己的 RSA 私钥
解开“小信封” → 还原出 AES 密钥
用 AES 密钥开“保险箱” → 还原出 原始文件
验证签名 → 确认身份与数据完整性
核心总结：那个包裹里到底是什么？
• 本体： AES 密钥 (它是解密正文的唯一钥匙)
• 外壳： RSA 加密后的密文 (它是保护钥匙的防护罩)

接收者的 RSA 公钥从何而来？
在非对称加密体系中，接收者（Receiver）首先会在本地生成一对密钥：私钥（自己藏好）和公钥（满世界宣告）。发送者获取公钥主要有以下三种途径：
🤝
1. 协议握手自动获取
这是最常见的形式（如 HTTPS 访问）。当你访问网站时，服务器会主动把包含公钥的证书推送到你的浏览器，无需你提前索取。
📜
2. 数字证书 (X.509) 最安全
接收者将公钥交给权威机构（CA）签名，生成证书。发送者通过下载证书获取公钥，并能通过 CA 的签名确认该公钥确实属于“那个接收者”。
📂
3. 公开查询/密钥服务器
在 PGP 邮件加密中，接收者会把公钥上传到公共的 Key Server。发送者只需根据接收者的邮箱地址，就能在服务器上搜寻到对应的公钥。
⚠️ 关键点：公钥不需要保密
公钥的职责是“加密”，而解密的权限掌握在私钥手中。因此，公钥就像是接收者的“银行账号”或者“收件地址”，它是故意让全世界知道的。发送者获取公钥的过程不需要加密，只需要确保公钥没被冒充即可（这正是数字证书存在的意义）。

为什么 Git 需要在本地生成 SSH 密钥？

当你使用 SSH 协议连接 GitHub/GitLab 时，本地生成的密钥对（Key Pair）扮演了“数字身份证”的角色。其核心目的在于解决以下三个问题：

1. 身份唯一性证明

私钥保存在你本地电脑，公钥上传到服务器。通过非对称加密算法，服务器能确信：提交代码的人确实是你，而不是冒充者。

2. 告别频繁输密码

相比 HTTPS 每次都要输入用户名和密码，SSH 通过后台的“挑战-响应”机制自动完成认证，极大提升了操作效率。

3. 极高的安全性

你的密码永远不会在网络上传输。即使服务器被黑客攻破，黑客拿到的也只是你的公钥，无法逆推出你的私钥，也无法假冒你。

💡 简单比喻：
这就像你在银行（GitHub）存了一个特制的锁头（公钥）。每次你要开保险箱时，你只需要在家里用你的专属钥匙（私钥）远程发一个指令，银行确认钥匙匹配后就会让你操作，而不需要你本人带着身份证和密码跑去柜台。
深度解析：SSL、TLS 与 SSH 的核心区别
🔄 历史演进关系：SSL ➔ TLS
SSL 是 TLS 的前身。它们是一类协议，只是版本不同。现在的“SSL 证书”本质上跑的都是 TLS 协议。
⚠️ 注意：SSL 协议由于漏洞已被强制废弃，请确保系统使用的是 TLS 1.2 或 1.3。
🌐 SSL / TLS 主流标准
  • 全称：传输层安全协议
  • 主要用途：保护 Web 流量 (HTTPS)、邮件发送 (SMTPS)。
  • 身份验证：基于 CA 数字证书。你需要向 CA 机构证明你是网站主人。
  • 典型端口：443 (HTTPS)。
💻 SSH 运维利器
  • 全称：安全外壳协议
  • 主要用途：远程登录、服务器管理、文件传输 (SFTP)。
  • 身份验证：基于 SSH 密钥对 或 账号密码。
  • 典型端口：22。
  • 特点：更强调双向命令交互。
🛡️ 核心区别总结表
维度 SSL / TLS SSH
本质职责 加密现有的数据通道 (如 HTTP) 建立一个远程管理的执行环境
信任基础 公钥基础设施 (PKI / 证书) 本地存储的信任名单 (Known Hosts)
受众群体 普通互联网用户 系统管理员、开发人员
形象比喻 🔐 银行柜台玻璃（保护你的钱不被中间人抢走） 🔑 家门钥匙（让你远程进入并操作自家的系统）
注：TLS 1.3 是目前最快、最安全的传输协议标准。
