Data 窗口与 Statistics 窗口

既要"精确数字"，又要"全局统计"——Data 窗口像数字仪表盘实时显示信号精确值，Statistics 窗口像统计报表汇总总线运行数据。两个窗口配合用，精确值和统计量都有了。

CANoe 11.0 SP2 Analysis 功能区 需关联 DBC（Data） 无需 DBC（Statistics）

Data 窗口要点

1. 打开方式

点 Analysis → Data，弹出 Data 窗口。新建空白工程默认不会自动打开，需手动点。一个工程可打开多个 Data 窗口，分屏摆放像汽车的双仪表盘。

2. 添加信号

在 Data 窗口空白处右键 → Add Signals...，按"数据库 → 报文 → 信号"树形结构选择。右键菜单还有：

  • Add Variables...：加系统变量或环境变量
  • Add Diagnostics Parameter...：加诊断参数
  • User Defined Signals：自定义虚拟信号，不依赖 DBC

3. 显示格式

格式显示内容示例适用场景
PhysicalDBC 转换后工程值，带单位87.5 km/h日常查看，最直观
RawDBC 转换前原始整数350底层调试，查信号编码
Decimal十进制显示87快速读数
Hexadecimal十六进制显示0x15E底层字节级分析
物理值 vs 原始值：DBC 里每个信号有转换公式（factor、offset）。如车速原始值 350，factor=0.25、offset=0，物理值 = 350 × 0.25 = 87.5 km/h。

4. 显示模式

模式显示内容适用场景
Current只显示当前最新值实时监控，看"现在多少"
Min/Max当前值 + 历史最小值 + 最大值监控波动范围，看"有没有超限"
注意：Data 窗口本身没有"平均值模式"。信号的平均值 (Average) 统计属于 Graphic 窗口功能——测量停止后，Graphic 可在曲线上显示 min/max/avg/std。

5. Signal Logging

Data 窗口工具栏支持信号记录，输出 MDF 格式（汽车领域常用测量数据格式）。注意：这里的记录只记录 Data 窗口里当前显示的信号，和 Measurement Setup 里的 Logging Block 不是一回事。

Statistics 窗口要点

1. 总线负载率（Busload）

总线被报文占用的时间百分比。500kbps 的 CAN 总线，负载率 30% 意味着总线 30% 的时间在传数据。

负载率状态说明
< 30%健康余量充足
30% - 50%偏忙峰值可能拥塞
50% - 70%繁忙有丢帧风险
> 70%危险可能出现通信故障
注意：30% 是业内常用安全红线，但不是绝对标准。刷写等场景短暂超过 50% 也正常，关键是稳态工况不要长期超过 30%。

2. 错误帧与错误计数

错误帧是 CAN 协议层面的错误（CRC 错误、位错误、格式错误等）。除了 Errorframes，还要关注 Transmit Error Count 和 Receive Error Count——它们比错误帧更敏感，持续增长但错误帧还没明显增加时，说明总线质量已经在恶化。

排查思路：错误帧持续增长时，先查终端电阻（CAN_H/CAN_L 各 120Ω，并联后 60Ω），再查波特率是否匹配，最后查线束有没有破损或接触不良。

3. 右键菜单

菜单项作用
Configuration...配置显示项、通道、统计参数
Adapt Columns Width自动调整所有列宽
Sort对统计项排序
Copy to Clipboard复制数据到剪贴板，粘贴到 Excel
Collapse / Expand All折叠/展开所有分组
Reset All Statistics清空累计值，从头开始统计
Pause All Statistics暂停统计，当前数值定格
提示：CANoe 11.0 SP2 的 Statistics 窗口右键没有独立的 Export CSV 入口，数据复制靠 Copy to Clipboard（制表符分隔），粘贴到 Excel 后另存即可。

一句话总结

窗口一句话典型场景
Trace看"每一帧是什么"排查单帧报文问题
Graphic看"信号怎么变"看加速曲线/温升过程
Data看"现在值多少"看车速精确读数
Statistics看"总线整体状态"负载率、错误帧、帧分布
搭配建议：Statistics 窗口和上面三个不在一个维度——上面三个看"信号/报文内容"，Statistics 看"总线运行状态"。它不跟信号窗口竞争，而是补充了一个全局视角。

常见问题排查

新手最常遇到的 5 个问题，点击展开查看原因和解决方案。

Q1：Data 窗口加不上信号（Add Signals 列表是空的）？ DBC
可能原因：
  • 工程没有关联 DBC 数据库，或者 DBC 里没有定义信号
解决方案：
  • 在 Simulation Setup 中右键通道 → Database，确认 DBC 文件已添加且无报错
  • 用 CANdb++ 打开 DBC，确认里面有报文和信号定义
  • 确认信号所在的报文确实分配给了当前通道（多通道工程容易搞混）
Q2：Data 窗口信号加上了但数值不刷新？ 数据
可能原因：
  • 测量没在 Running——检查左下角状态
  • 该信号所在报文根本没在总线上发
  • 信号值确实没变化——事件触发信号不变化是正常的
解决方案：
  • 先看 Trace 有没有对应报文在发
  • 如果有报文但 Data 不刷新，检查信号是否正确关联到该报文
  • 如果报文在发、信号也正确，可能是信号值本身没变化（稳态），属于正常现象
Q3：Statistics 窗口的总线负载率一直显示 0？ 统计
可能原因：
  • 测量没在 Running——Statistics 只统计运行期间的数据
  • 总线上没有报文——空跑的总线负载率就是 0
  • 通道配错——Statistics 统计的是当前激活通道
解决方案：
  • 先确认 Trace 窗口有报文在滚动（证明总线有数据）
  • 确认 Statistics 窗口统计的通道与实际有报文的通道一致
  • 如果 Trace 有报文但 Statistics 负载率为 0，尝试关闭重开 Statistics 窗口
Q4：Statistics 窗口里 Std./Ext. Data 速率异常？ 帧率
可能原因：
  • 发送节点的周期配置有误——CAPL 里 setTimer 周期写错
  • 多个节点发送同一 ID 的报文——重复发送导致帧率翻倍
  • 报文被丢失——总线负载过高时部分帧被丢弃，计数偏低
解决方案：
  • 去 Trace 窗口过滤该 ID，观察实际发送间隔是否均匀
  • 检查 Simulation Setup 里发送节点的 CAPL 代码，确认 setTimer 周期
  • 检查总线负载率是否过高导致丢帧
Q5：Copy to Clipboard 粘贴到 Excel 后格式错乱？ 导出
可能原因：

Statistics 窗口复制的是制表符分隔的文本，Excel 粘贴时没自动按列分列，导致所有数据挤在一列。

解决方案：
  • 粘贴到 Excel 后选中该列 → 数据 → 分列 → 选择「分隔符号」→ 勾选「Tab 键」→ 完成
  • 或者先粘贴到记事本保存为 .txt，再用 Excel 的「数据 → 从文本/CSV」导入，分隔符选 Tab

知识小结

核心要点速查表，一页回顾全部知识点。

Data 定位

数字仪表盘，实时显示信号当前精确值

Data 打开方式

Analysis → Data

Data 前提条件

必须关联 DBC，才能添加信号

Data 显示格式

Physical 物理值 / Raw 原始值 / Decimal 十进制 / Hex 十六进制

Data 显示模式

Current 单值 / Min-Max 最小最大（Data 无 Average；平均值在 Graphic 窗口）

Statistics 定位

统计报表，汇总总线运行数据

Statistics 打开方式

Analysis → Statistics

Statistics 前提条件

不依赖 DBC，统计报文层数据

Statistics 统计项

Busload、帧类型分布（Std/Ext Data/Remote）、Errorframes、Chip State、错误计数等

Statistics 右键菜单

Configuration / Adapt Columns / Sort / Copy to Clipboard / Collapse / Expand / Reset / Pause

负载率红线

稳态 < 30% 健康，> 70% 危险

数据复制

Statistics 右键 → Copy to Clipboard，粘贴到 Excel/记事本

Data 窗口记录

工具栏 → Signal Logging Configuration / Start Logging，输出 MDF

三窗口搭配

Trace 看细节 + Graphic 看趋势 + Data 看读数

实战经验

调台架时常用最小最大值模式监控关键信号。比如刹车压力信号，跑一圈看最大值有没有达到预期，比逐帧翻 Trace 快太多了。

错误帧持续增长时，排查顺序：终端电阻 → 波特率匹配 → 线束破损/接触不良。Transmit/Receive Error Count 比错误帧更敏感，是总线质量恶化的早期信号。
