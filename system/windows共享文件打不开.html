1. SAM 账户与远程桌面 (RDP) 的绑定关系

核心逻辑：SAM (Security Accounts Manager) 是 Windows 的本地用户数据库。当你通过 RDP 登录远程电脑时，如果你使用的是本地账号（非域账号），系统本质上就是去查目标机的 SAM 文件。

并不是所有的远程桌面都是通过 SAM 认证的，这取决于你的账户类型：

  • 本地登录 使用 C:\Windows\System32\config\SAM 数据库中的哈希值比对。
  • 域登录 绕过本地 SAM，由域控制器 (Active Directory) 的 ntds.dit 数据库负责。

定义：SAMR (Security Account Manager Remote Protocol) 是一套基于 RPC 的协议，允许远程管理本地 SAM 数据库中的用户、组和密码。

当你从 A 电脑远程修改 B 电脑的用户密码，或者在域控上管理成员机账号时，调用的就是 SAMR 协议。

核心概念：身份验证的两大基石

SAM (Security Accounts Manager) 是单机时代的“管家”，负责管理本地账户；
域认证 (AD DS) 是企业级的“中央司令部”，基于 Kerberos 协议实现多主机统一登录（SSO）。

1. 域认证核心：Kerberos 与 NTLM

Kerberos 流程（现代域控默认）： 通过“票据”机制，避免在网络中传输明文密码或哈希。

⚖️ 域认证 vs SAM 本地认证 (PK)

维度 域认证 (Enterprise) SAM 本地认证 (Standalone)
管理成本 极低：中央修改，万台机器同步生效。 极高：每台机器都要手动改密码。
安全性 高：支持 Kerberos 票据、双因子。 中：易受本地提权、离线哈希破解。
便利性 (SSO) 一键登录：登录系统后访问共享无需密码。 频繁弹窗：每次访问共享都要输账号。
离线支持 弱：断网后依赖缓存登录。 强：完全不依赖网络。
🚩 结论：哪个更好？
  • 企业/组织环境：域认证完胜。 它是实现权限审计、统一管控、自动化运维的唯一手段。
  • 个人/家庭环境：SAM 更好。 无需额外部署域控服务器，简单直接，不依赖网络连接。
  • 混合模式： 建议域认证作为主选，SAM 作为“后门”维护账号（如 Administrator）仅在域控挂掉时应急。

1. SMB (Server Message Block) 核心协议栈
SMB 是典型的客户端-服务器 (C/S) 协议。它不仅用于文件共享，还是 Windows 远程管理 (RPC)、打印服务的基石。
  • 常用端口： 现代 Windows 统一使用 TCP 445。老旧版本可能用到 UDP 137/138 和 TCP 139 (NetBIOS)。
  • 版本演进：
    • SMB 1.0 (CIFS)： 极度不安全（勒索病毒 WannaCry 利用的对象），建议禁用。
    • SMB 2.1： Win7 引入，极大地优化了高延迟网络下的性能。
    • SMB 3.1.1： Win10/11 核心，支持强制加密、多通道加速 (Multichannel)。
graph LR Client["客户端 (Win10)"] -- "TCP 445 握手" --> SMB_Srv["远程 SMB 服务器"] SMB_Srv -- "Negotiate (协议协商)" --> Client Client -- "Session Setup (带账号密码)" --> SMB_Srv SMB_Srv -- "验证权限 (NTLM/Kerberos)" --> Success["✅ 建立连接 (映射盘符)"]
2. SAM (Security Accounts Manager) 本地鉴权中枢
SAM 是 Windows 的“户口登记本”，存储在 C:\Windows\System32\config\SAM，系统运行时该文件被强制锁定，无法直接读取。
  • 存储内容： 本地用户名、组关系、以及最重要的 NTLM 哈希值（不存明文密码）。
  • 验证机制： 当你通过 SMB 连接时，系统将你输入的密码计算出哈希，与 SAM 里的哈希对比，一致则通过。
  • 局限性： SAM 仅针对本地账户。如果公司有几千台电脑，SAM 无法同步，必须升级到域 (Active Directory)。
3. 哪个更好？(协作与场景对比)
结论： 这两者不是“竞争关系”，而是“协作关系”。SMB 是传输方式，SAM 是本地验证手段。
维度 远程 SMB 本地 SAM
角色 搬运工 (传输协议) 门卫 (账号数据库)
存储位置 网络中的任何共享目录 服务器本地注册表/硬盘
安全性 靠 SMB 加密和访问限制 (ACL) 靠 NTLMv2 哈希和 SYSKEY 加密
适用范围 多机通信、文件交换 单机登录、工作组共享验证

2. 关键组策略设置 (Lanman Workstation)

您报错图片中的问题，本质上是由于 Windows 10/11 在 1709 版本后，为了防御勒索病毒，默认禁用了 "不安全的来宾登录"。
启用不安全的来宾登录
AllowInsecureGuestAuth

允许客户端在没有提供凭据的情况下，以来宾身份访问远程共享。修复“组织策略阻止”问题的唯一开关。

启用 SMB 签名
EnableSecuritySignature

要求在数据包中包含数字签名，防止中间人篡改。开启后会略微降低传输性能。

启用硬化路径
HardenedPaths

针对特定共享路径强制执行最高安全级别（如签名、加密），通常用于域控制器的 SYSVOL 共享。
