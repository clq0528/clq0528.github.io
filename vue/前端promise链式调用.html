1 聚合执行：Promise.all() All or Nothing

核心逻辑： 接受一个 Promise 数组，只有当所有成员都成功时才返回成功数组；只要有一个失败，整体立即宣告失败。
graph LR Input["Promise 数组 [p1, p2, p3]"] --> Executor["Promise.all 调度器"] Executor --> P1["p1 (100ms)"] Executor --> P2["p2 (500ms)"] Executor --> P3["p3 (200ms)"] %% 全部成功的分支 P1 & P2 & P3 -- "全部成功" --> Success(["[res1, res2, res3]"]) %% 任一失败的分ize，使用分开指向来表达逻辑 P1 -- "任一失败" --> Reject P2 -- "任一失败" --> Reject P3 -- "任一失败" --> Reject Reject(["立即触发 .catch()"]) style Success fill:#f6ffed,stroke:#52c41a style Reject fill:#fff1f0,stroke:#ff4d4f

2 竞速模式：Promise.race() Fastest Wins

核心逻辑： 数组中哪个 Promise 先执行完（无论成功还是失败），就返回那个结果，其余结果被忽略。常用于请求超时控制。

2 决策指南：如何选择? Decision Table

优先使用 Promise 的场景

  • 需要执行 **并发操作** (如 Promise.all)
  • 简单的一次性异步逻辑
  • 函数式编程风格的项目

优先使用 async/await 的场景

  • 有 **前后依赖** 的复杂异步流程
  • 复杂的错误处理逻辑 (try/catch 更直观)
  • 需要打断点单步调试异步代码

1 宏观逻辑：从数组到 Promise 链 Array.reduce Pattern

语法解析： reduce 的初始值是 Promise.resolve()。在每次迭代中，我们把上一个 Promise (chain) 拿出来，用 .then() 挂载一个新的异步任务。这就像在修铁路，一节一节往后接。
graph LR Init["初始值: Promise.resolve()"] --> Link1["chain.then(Day 1)"] Link1 -- "等待 Day 1 完成" --> Link2["chain.then(Day 2)"] Link2 -- "等待 Day 2 完成" --> Link3["chain.then(Day 3)"] Link3 -- "..." --> Final["所有任务串行结束"] style Init fill:#f6ffed,stroke:#52c41a style Final fill:#e6f7ff,stroke:#1890ff

2 微观执行：chain.then(() => ...) 的闭包机制 Iteration Logic

语法关键： chain.then 内部必须 return 一个新的 Promise（即 fakeApiCall 的返回结果），这样 reduce 的累加器才能接收到这个未完成的状态，从而实现“排队执行”。
graph LR Input["当前日期参数 (param)"] --> Prev["上一个 Promise 状态 (chain)"] Prev -- "当状态变为 Fulfilled" --> Callback["触发 .then() 回调函数"] Callback --> API["执行 this.fakeApiCall(param)"] API -- "网络请求中..." --> Processing["处理数据 & 更新进度条 %"] Processing --> UpdateUI["this.$refs.modalForm.edit(...)"] UpdateUI --> Return["return 结果 (作为下一次的 chain)"] Return --> Next["进入下一次 reduce 循环"] style API fill:#f9f0ff,stroke:#722ed1 style UpdateUI fill:#fff7e6,stroke:#faad14

3 终点汇总：allData 的归宿 Final Aggregation

逻辑说明： 所有的 fakeApiCall 结果都通过闭包被 push 进 allData 数组。当 reduce 彻底跑完，最后的 .then() 会拿到完整的 allData 进行汇总请求或导出。
graph LR subgraph Iteration ["异步迭代区间 (30~365次)"] D1["Day 1 Data"] D2["Day 2 Data"] DN["Day N Data"] end Iteration -- "push" --> Collector["allData 缓冲区"] Collector -- "串联结束" --> FinalCheck{"isExport?"} FinalCheck -- "Yes" --> Export["downloadExcel(allData)"] FinalCheck -- "No" --> Summary["finalApiCall(allData)"] Summary --> Render["更新表格 dataSource"] style Collector fill:#fff1f0,stroke:#ff4d4f style Render fill:#f6ffed,stroke:#52c41a

4 代码语法骨架解读 Syntax Anatomy

return dateParams.reduce((chain, param) => {

return chain.then(() => {

// 这里的 return 是关键：它将 api 的 Promise 传给累加器

return this.fakeApiCall(param).then(data => { ... });

});

}, Promise.resolve());

为什么不用 Promise.all？ 如果日期范围是一年（365天），Promise.all 会瞬间发出 365 个并发请求，导致浏览器挂起或后端网关限流。reduce 方案每次只发一个请求，用户能看到进度条一点点走动，体验极佳。
