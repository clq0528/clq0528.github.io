1. INDEX (RANGE SCAN) —— 索引范围扫描 性能评价：优良 (High Efficiency)

这是数据库访问数据的一种“高效路径”。

字面意思

按照一定的“范围”去搜寻索引树。

技术原理

Oracle 的索引通常是 B-Tree (平衡树) 结构。范围扫描意味着优化器在索引中找到了起始点，然后沿着索引的叶子节点水平扫描，直到达到终止点。

graph LR Start((开始)) --> Seek[B-Tree 根节点寻址] Seek --> Leaf[定位初始叶子节点] Leaf --> Scan[水平顺序遍历叶子节点] Scan --> Stop{达到范围边界?} Stop -- No --> Scan Stop -- Yes --> End((结束))

什么情况下会出现？

  • 范围操作符：如 WHERE ID > 10 或 WHERE ID BETWEEN 1 AND 100。
  • 前缀匹配：如 WHERE NAME LIKE '张%'。
  • 非唯一性索引：即便搜索 WHERE NAME = '张三'，若该字段非唯一，Oracle 会扫描范围以确保找全所有“张三”。
📖 形象类比：查字典
就像你在查字典。你翻到“张”字开头的页码，然后在那几页里从上往下找，直到找到不是“张”字为止。这叫按范围找。
2. VIEW —— 视图操作 (或虚拟中间表) 性能评价：中性 (Intermediate)

代表 Oracle 正在处理一个“无法合并的子查询”或“临时结果集”。

字面意思

并非手动创建的数据库视图，而是指一个中间处理环节产生的虚拟表。

技术原理

当 SQL 语句包含 UNION, DISTINCT, GROUP BY 或复杂子查询时，优化器无法将逻辑“拍平”。流程如下：

graph LR Sub[执行独立子查询] --> Temp[生成临时结果集/VIEW] Temp --> Upper[供上层 JOIN/递归使用] style Temp fill:#e6f7ff,stroke:#1890ff

截图场景分析 (VW_NSO_1)

  • VW_ 前缀：代表 Virtual View，由优化器内部生成的临时视图。
  • 上下文逻辑：底层 UNION-ALL 和 SORT (UNIQUE) 的结果被打包成 VW_NSO_1，再与外部的 NESTED LOOPS 进行关联。
📋 形象类比：复印件小册子
就像你先从几本书里复印了一些资料，把这些复印件整理成一个临时小册子放在桌上。接下来的工作中，你不再去翻那几本书，而是直接翻这个小册子。这个小册子就是 VIEW。

这里的 INDEX (RANGE SCAN) 成本极低 (Cost=3)。说明过滤条件有效命中了索引 `I_LINK_DATA_SN`，避免了全表扫描，是此计划中最健康的访问路径。

⚠️ 潜在隐患：
