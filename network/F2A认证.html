双因素认证 (2FA) 核心技术全景图

基于身份认证三要素，拆解 TOTP 动态密码、硬件令牌及代理服务器的交互机制。

2FA 即从以下三个维度中任选两个维度进行组合，通常为“所知”+“所有”。

2 传统静态密码的安全隐患 Static Password Vulnerability

静态密码易受社工、撞库、字典攻击及窥视泄露，且用户倾向于设置简单易记的弱密码。

1 初始注册：共享密钥分发 Secret Provisioning

服务器生成唯一的种子密钥，并通过二维码等安全渠道告知客户端。
graph LR SrvGen["服务器生成 Secret Key"] --> DB["存入数据库 (关联用户)"] SrvGen --> QR["生成包含密钥的二维码 (Base32)"] QR --> UserScan["用户使用 APP 扫描"] UserScan --> ClientStore["客户端本地安全存储密钥"] style QR fill:#fff7e6,stroke:#faad14

2 客户端：动态验证码计算 Code Generation Logic

基于时间戳和密钥，每30/60秒生成一个一次性哈希值。
graph LR Time["当前时间戳 (Unix Epoch)"] --> Step["步长计算: T = Floor(Time / 30)"] Step --> HMAC["HMAC-SHA1 (Secret, T)"] HMAC --> Truncate["动态截断 (Dynamic Truncation)"] Truncate --> Code["生成 6 位数字 OTP"] style HMAC fill:#f9f0ff,stroke:#722ed1 style Code fill:#e6f7ff,stroke:#1890ff

3 服务端：同步与匹配校验 Server Verification

服务器使用相同的算法计算，并考虑网络延迟导致的时间偏移。
graph LR Submit["用户提交 OTP"] --> Fetch["调取用户关联的 Secret"] Fetch --> Cal["计算当前时间窗口及前后 T±1 的 OTP"] Cal --> Match{"任意一个匹配成功?"} Match -- 是 --> OK["验证通过"] Match -- 否 --> Fail["验证失败 (尝试次数限制)"] style Match fill:#fff7e6,stroke:#faad14 style OK fill:#f6ffed,stroke:#52c41a
