1 Fiddler 核心工作机制 Proxy & MITM Architecture

Fiddler 作为一个系统代理（默认端口 8888），它介于客户端（浏览器/App）和服务器之间。它劫持 WinINET 协议栈请求，并作为中间人重发数据。

1 证书信任链与安装流程 Certificate Chain Installation

Fiddler 在首次启用 HTTPS 解密时，会生成一个自签名的根证书 (FiddlerRoot)。用户必须手动将此证书安装到系统的“受信任的根证书颁发机构”存储区，浏览器才会信任 Fiddler 后续动态签发的站点证书。
graph LR Start["首次打开 HTTPS 解密"] --> GenCert["生成 FiddlerRoot 证书"] GenCert --> Export["导出 .cer 文件到桌面"] Export --> Manual["手动安装向导"] Manual --> TrustStore["存入“受信任的根证书颁发机构”"] TrustStore --> Trusted{系统是否信任?} Trusted -- 是 --> Success["✅ 后续所有站点证书自动信任"] Trusted -- 否 --> Error["❌ 浏览器显示“不安全连接”警告"] style TrustStore fill:#f6ffed,stroke:#52c41a style Error fill:#fff2f0,stroke:#ff4d4f

2 动态证书生成与 TLS 握手拦截 Dynamic Cert Generation

对于每个新的 HTTPS 站点，Fiddler 会实时用根证书私钥签发一个专属于该站点的“伪造”证书。此过程对用户透明，但实现了对加密链路的完全控制。
graph LR Client["浏览器访问 https://example.com"] --> Hello["ClientHello"] Hello --> Fiddler["Fiddler 拦截"] Fiddler --> CheckCert{"证书缓存是否存在?"} CheckCert -- 否 --> Generate["用 FiddlerRoot 私钥即时生成 example.com 证书"] CheckCert -- 是 --> Load["从缓存加载已有证书"] Generate --> Sign["签名并返回给浏览器"] Load --> Sign Sign --> Establish1["与浏览器建立 TLS 隧道 1"] Establish1 --> ConnectReal["Fiddler 以真实客户端身份连接真实服务器"] ConnectReal --> Establish2["与真实服务器建立 TLS 隧道 2"] style Generate fill:#f9f0ff,stroke:#722ed1 style Establish1 fill:#e6f7ff,stroke:#1890ff

1 断点 (Breakpoint) 设置与拦截点 Request/Response Breakpoints

断点允许在请求发出前或响应返回后暂停会话，以便修改其内容。这是动态调试 API 行为的核心手段。

2 AutoResponder 规则引擎与匹配逻辑 Rule Matching & Action

AutoResponder 通过预定义规则（支持通配符和正则表达式）自动匹配请求，并用本地文件或重定向 URL 替换原始响应，用于模拟接口返回、调试前端或制造异常场景。
