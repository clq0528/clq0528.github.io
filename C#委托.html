C# 委托 (Delegate) 交互教学

拟物化隐喻： 委托就像一个“多功能插座”。你可以把不同的“电器”（方法）插上去执行。
【知识点】委托是一种定义方法签名的类型，可封装和执行方法，事件是特殊的委托

委托插座 (Action)
方法A: 送货
方法B: 打印

多语言类比：谁才是委托？

C# (Delegate)

// 声明：自定义delegate（支持0-32个参数，可指定返回值）
delegate void MyDel(string s);
// 使用：关联兼容签名的方法
MyDel del = Console.WriteLine;
del("Hi");

JavaScript (Callback)

// 声明
// JS中函数是一等公民
const del = (s) => 
  console.log(s);
// 使用
del("Hi");

Java (Functional)

// 声明
Consumer<String> del = 
  System.out::println;
// 使用
del.accept("Hi");

委托四大类型可视化 (JSXGraph)

通过输入输出观察 Predicate 和 Func 的区别：
【知识点】现代C#中Action/Func支持0-16个参数（早期版本为4个）

Action

无返回值（void）。支持0-16个参数，类似 JS 的 void function
示例：Action<int, string>（两个参数，无返回值）

Func<T, res>

必须有返回值。支持0-16个输入参数，最后一个泛型为返回类型，类似 Java 的 Function<T,R>
示例：Func<int, string>（int参数，返回string）

Predicate<T>

仅接受1个参数，返回值固定为bool。常用于集合筛选（Array.Find/List.FindAll），类似 Java 的 Predicate<T>
示例：Predicate<int> p = x => x > 100;

核心逻辑与设计说明

一、委托四大类型总结

参考来源：C# 的四种委托实现详解

  • 1. delegate：0-32个参数，返回值任意/无
  • 2. Action：0-16个参数，无返回值（void）
  • 3. Func：0-16个输入参数，必须有返回值（最后一个泛型为返回类型）
  • 4. Predicate：仅1个参数，返回值固定为bool

二、交互设计与知识点映射

  • 拟物化 (Neumorphism) 设计：页面使用柔和的阴影（box-shadow）模拟物理表面的凸起和凹陷，让初学者感觉到“方法”是可以被“移动”和“插拔”的实体。
  • GSAP 交互动画 (3.1 - 3.4 节内容)：
    • 绑定 (Bind)：点击“绑定方法”，方法块平滑移动到委托中心，演示 method = new MethodDelegate(Add) 的过程。
    • 执行 (Invoke)：点击“执行委托”，橙色光球从委托插座传向绑定方法，模拟委托作为“中间人”调用目标方法的过程。
    • 清空 (Clear)：演示 OnDelegate = null 的物理回归。
  • 多语言类比 (2.5 节内容)：
    • JavaScript 类比：强调 JS 函数可直接作为参数传递（Callback），对比 C# 需先定义类型的严谨性。
    • Java 类比：将 C# 的 Action/Func 与 Java 8 的 Consumer/Function 接口一一对应，帮助Java初学者理解 Func<T, res> 即 Function<T, R>。
  • JSXGraph 逻辑可视化 (2.4 节内容)：专门针对 Predicate，通过可拖动的蓝色点，当坐标大于100时文本为绿色“True”，小于100时为红色“False”，直观展示 Predicate 的唯一职责：根据输入（T）返回布尔判断。
